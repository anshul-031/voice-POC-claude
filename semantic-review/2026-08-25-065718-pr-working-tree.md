# Live voice-call diagnostics and relay instrumentation

This working-tree change adds diagnostics across browser capture/playback, WebSocket signaling, Gemini transport, telephony relay, call summaries, and recording finalization. It keeps raw payloads out of the added logs and replaces the prior prompt snippet with a prompt length. The remaining risks are an unreachable audio-warning throttle, pre-send relay accounting, recorder counters reset before asynchronous finalization, and repeated base64 decoding on the real-time path.

Watch for: **confirmed** malformed audio still reaching an unthrottled warning; **confirmed** failed model sends counted as delivered; **confirmed** recorder-stop metrics reset too early; **confirmed** extra base64 allocations per audio chunk.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** the audio warning helper sits below the connection-level schema gate, while its counter map is cleared only on socket error/close. Malformed audio therefore bypasses throttling, and session reuse can retain prior counts.

**Confirmed:** model relay state is committed before browser or telephony `send` succeeds, so a caught send failure can still affect first-audio and inactivity diagnostics.

**Confirmed:** `endCall()` closes the audio context and resets recording counters before asynchronous MediaRecorder stop events finish, making the new stop metrics unreliable.

**Confirmed:** metrics decode base64 independently in several Gemini, signaling, and telephony paths, adding avoidable allocation and CPU work to audio processing.

<details>
<summary>Issues (4)</summary>

1. **Malformed-audio warning throttle bypass** — **Medium, confirmed.** The outer signaling schema rejects malformed `audio-data` before `_handleAudioData` can use the throttled helper, so the generic warning and error response still occur for every message. Route audio-schema failures through the same throttle and add an end-to-end regression test.
2. **Connection-level warning counters survive call termination** — **Medium, confirmed.** The map is keyed by connection correlation ID and cleared only from socket `close`/`error`; normal end, auto-end, Gemini close, and direct disconnect cleanup do not clear it. Clear counters on every terminal session path or key them to a per-call ID.
3. **Failed model sends are recorded as delivered** — **Medium, confirmed.** Model counters, first-audio timing, and `lastModelResponseAt` update before browser/telephony `send`; the catch then records failure while progress still says the chunk was relayed. Commit delivered-state metrics only after success, or separate attempted and delivered counters and exclude failures from response timing.
4. **Recorder finalization races the diagnostics reset** — **Medium, confirmed.** The stop callback reads global recording counters after `endCall()` has closed the context and reset them, so asynchronous final events can log zero or partial counts. Keep per-recorder snapshots and reset only after finalization, or emit the final summary from the stop event.

<summary>Details</summary>

### Malformed-audio warning throttle bypass

The connection handler validates the complete message at `src/services/signalingServer.ts:116-129`. A payload such as `{type: "audio-data", data: ""}` fails there and produces `Invalid signaling message payload` immediately. The new throttled helper at `src/services/signalingServer.ts:67-89` is only reachable from `_handleAudioData` at `src/services/signalingServer.ts:1043-1058`, after the same audio schema has already passed through the outer discriminated union. The high-volume malformed-audio case remains unthrottled and still sends an error response for every message.

### Connection-level warning counters survive call termination

`audioDiagnosticCounters` is keyed with the connection-scoped correlation ID at `src/services/signalingServer.ts:67-74`, but cleanup is only wired into socket `close` and `error` at `src/services/signalingServer.ts:161-184`. `_handleEndCall` deletes the client at `src/services/signalingServer.ts:1121-1138`, `_autoEndCall` deletes it at `src/services/signalingServer.ts:1471-1493`, and the Gemini `onClose` callback deletes it at `src/services/signalingServer.ts:679-691`; none clears the counters. A long-lived socket that starts another session retains the previous throttle count and can suppress the next call’s first warning.

### Failed model sends are recorded as delivered

`_recordModelAudioMetrics` updates the client at `src/services/signalingServer.ts:343-361`, including `lastModelResponseAt` and first-model-audio timing, before routing. Browser send failures are caught at `src/services/signalingServer.ts:438-461`, and telephony failures at `src/services/signalingServer.ts:517-548`, but both execute after the state update; browser progress logging also runs after the catch. A send failure can therefore produce “First model audio relayed” and advance inactivity timing even though no audio reached the client/provider.

### Recorder finalization races the diagnostics reset

The new `onstop` diagnostic reads `recordingChunkCount` and `recordingBytes` at `public/js/call.js:730-743`. `endCall()` closes the audio context before invoking the helper at `public/js/call.js:1136-1183`, then logs the call summary and resets those counters at `public/js/call.js:1188-1203`. MediaRecorder data and stop events are asynchronous, so the callback can run after the reset and report zero despite a non-empty recording. The helper’s boolean only says that `stop()` was invoked; it does not provide a stable final counter snapshot.

### Avoidable base64 work on the audio hot path

The added metrics decode each payload for byte counts in Gemini logging at `src/services/geminiLiveLogging.ts:20-22`, Gemini input transport at `src/services/geminiLiveTransport.ts:6-10`, browser signaling at `src/services/signalingServer.ts:1071-1075`, and model output signaling at `src/services/signalingServer.ts:343-354`. Telephony decodes again for resampling and recording at `src/services/signalingServer.ts:517-521` and `src/services/signalingServer.ts:1276-1308`, with another periodic decode for logging. Derive byte counts from validated base64 metadata or pass/reuse the decoded buffer instead of allocating per metric path.
